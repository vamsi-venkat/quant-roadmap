Research & Backtesting Best-Practice Guide

How professional quantitative research is structured, and why most backtests fail in live trading.

The Research Process

1
Form a falsifiable hypothesis. "Stocks with high trailing 12-month momentum earn positive risk-adjusted returns in the subsequent month" — this is testable and falsifiable. Avoid "the market has patterns I can exploit" — untestable.
2
Inspect data before modeling. Check for outliers, missing observations, corporate actions, survivorship bias, point-in-time availability. Many apparent signals disappear after data cleaning.
3
Establish a baseline first. What does a simple benchmark do? Equal-weight buy-and-hold, market-cap weighted index. Your strategy must clearly beat this, net of costs, in OOS data.
4
Choose the model. Prefer the simplest model that fits the hypothesis. A linear regression with 3 factors is preferable to XGBoost with 50 features if their predictive power is similar — less overfitting risk, more interpretable.
5
Run experiments in-sample only. Log ALL experiments (use MLflow). Make OOS data invisible during model development.
6
Validate OOS exactly once. If you revisit OOS to improve the model, it becomes in-sample. A second OOS period is now contaminated.
7
Assess robustness. Does the strategy work across subperiods? Asset classes? Parameter perturbations? A good strategy is robust; a fit strategy is fragile.
8
Document limitations honestly. All strategies have failure modes. Write them in your research report. Reviewers trust researchers who acknowledge limitations over those who don't.

The Taxonomy of Backtesting Biases

🚫 Survivorship Bias

Testing only on currently traded companies excludes delisted, bankrupt, or acquired firms — systematically overestimates returns. Fix: Use point-in-time constituent lists. Bloomberg, CRSP, and Compustat provide these; free approximations exist via Wikipedia S&P 500 historical membership.

🚫 Look-Ahead Bias

Using data that wasn't available at decision time. Common in accounting data (10-K filed 60+ days after quarter end). Fix: Use point-in-time financial databases (Compustat); always lag fundamental data by at least 3 months.

🚫 Data Snooping / Multiple Testing

Testing 100 parameter combinations; 5 will appear significant by chance at α=5%. Fix: Apply Bonferroni correction; report all tested parameters, not just the best; compute Probability of Backtest Overfitting (PBO). Harvey, Liu & Zhu (2016) recommend minimum t-stat of 3.0 for new factor claims.

🚫 In-Sample Overfitting

A model trained on historical data learns noise, not signal. Fix: Purged K-fold CV; walk-forward validation; regularization; hold-out test set that is never touched during development.

🚫 Transaction Cost Underestimation

Using zero or 1bp costs; ignoring market impact for larger positions; ignoring borrow costs for short positions. Fix: Use bid-ask midpoint for signals; apply 5–15bps per-side for liquid large-caps; add a market impact model for strategies with large AUM.

🚫 Non-Stationarity & Regime Changes

Statistical relationships change over time. The value premium that worked 1963–2007 has been largely absent post-2007. Fix: Subsample analysis; regime detection; avoid strategies that depend entirely on one period's patterns.

Sharpe Ratio — Limitations and Context

⚠️

Sharpe ratio assumes returns are i.i.d. Normal. Real returns are: (1) autocorrelated (inflating Sharpe for trend-following), (2) non-normal (fat tails understate risk), (3) estimated with finite samples (a Sharpe of 1.5 over 3 years has wide confidence intervals). Use Deflated Sharpe Ratio (Bailey & Lopez de Prado 2012) which adjusts for skewness, kurtosis, and multiple testing. A 3-year monthly Sharpe of 1.5 has a 95% CI of approximately [0.8, 2.2]. Always report the confidence interval.

Walk-Forward Validation Protocol

❌ Never Do This

Optimize parameters on full dataset, then test on same dataset. Report Sharpe = 2.3. "Our strategy works."

⚠️ Acceptable But Weak

Single train/test split, 70%/30%. Better, but vulnerable to regime luck — if the test period is a bull market, you get false confidence.

✅ Do This

Walk-forward: IS=36m, OOS=6m, step=6m, 10+ folds. Each fold optimizes independently. Report aggregate OOS performance across all folds, including the worst fold.

  1. Python + NumPy + pandas — the tool you'll use for everything else. No shortcuts here.

  3. Linear regression — understand OLS, its assumptions, when it fails, and what alternatives exist.

  7. Black-Scholes + Greeks — you will be asked about this in any interview.
  8. Fama-French + Fama-MacBeth — the standard empirical framework for factor research.
  9. Backtesting biases — know these so well you can cite them in your sleep.
  10. Git & reproducible workflows — professional non-negotiable.

🚫 AVOID / DEFER

  1. Deep Learning / Neural networks before mastering linear models — skip-level overfitting guarantees failure
  2. Crypto strategies early on — regime instability, thin microstructure, data quality issues make it harder to learn clean lessons
  3. RL for trading — requires enormous data, non-trivial environment design; defer until year 2+
  4. High-frequency trading without microstructure foundations — requires expensive data and infrastructure
  5. Paid courses with no code — avoid courses that promise "profitable strategies" without teaching statistics
  6. Copying tutorial strategies verbatim — you learn nothing and it's obvious in interviews
  7. Over-engineering before understanding — don't build a distributed backtester before you can run a simple walk-forward correctly
  8. Chasing every new paper or method — go deep before going wide
🎯

Final Principle — From Your Research Supervisor:

The most common mistake beginners make is treating quant finance as pattern recognition: find a pattern in historical data, code it up, report the backtest. That approach produces overfit strategies and shallow understanding. The approach that builds real expertise is scientific thinking: form a precise hypothesis about why a pattern should exist (risk premium, behavioral bias, structural friction), design a test that could genuinely falsify it, apply every bias control, accept the result honestly. A strategy that fails a rigorous test is not wasted time — it's a lesson in what the market doesn't reward. That understanding is worth more than any overfit backtest.
