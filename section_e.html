01

Financial Data Pipeline & Exploratory Analysis

Beginner Python · pandas · yfinance ~15 hours

Research Question: What are the empirical statistical properties of daily equity returns, and how do they differ from the Gaussian assumption underlying classical finance theory?

Methodology

  • Download 10+ years of OHLCV data for 20 large-cap stocks plus SPY using yfinance
  • Handle splits, dividends, and missing data explicitly
  • Compute log-returns: r_t = ln(P_t/P_{t-1})
  • Statistical description: mean, std, skewness, excess kurtosis, Jarque-Bera test for normality
  • Plot: histogram vs fitted Normal vs fitted Student-t, QQ-plot, rolling volatility
  • Autocorrelation of returns (ACF) vs autocorrelation of |returns|
  • Measure maximum drawdown, rolling Sharpe ratio

Expected Findings & Why They Matter

  • Fat tails: kurtosis > 3 — Black-Scholes underprices OTM options
  • Negative skewness in equity indices — asymmetric risk
  • Near-zero autocorrelation in returns (consistent with weak-form EMH) but strong autocorrelation in |returns| (volatility clustering)
  • Student-t distribution (ν ≈ 3–5 df) fits much better than Normal

What Makes It Interview-Credible

  • State the Jarque-Bera test statistic and its p-value; explain what it tests
  • Discuss the implications of fat tails for risk management (VaR underestimation)
  • Include a proper data provenance section — where data came from, adjustments made
Deliverables: GitHub repo · Jupyter notebook with reproducible code · README explaining statistical findings · All charts as PNG
02

Return, Volatility, Correlation, and Drawdown Analysis

Beginner–Intermediate NumPy · pandas · scipy ~20 hours

Research Question: How do volatility, correlation, and drawdowns behave across different market regimes, and what are the practical implications for portfolio construction?

Methodology

  • Realized volatility: rolling 21-day std × √252; rolling 63-day
  • Compare realized vol, EWMA vol (λ = 0.94, RiskMetrics), and implied vol (VIX proxy)
  • Rolling correlation matrix: 60-day, 252-day windows — animate how correlations spike in crises
  • Compute maximum drawdown, drawdown duration, underwater curve
  • Conditional distributions: return distributions conditioned on VIX quintiles
  • Volatility-of-volatility measure (standard deviation of rolling vol)

Key Insight to Demonstrate

  • Correlation instability: correlations are high in stress — diversification fails when you need it most (Ang & Chen 2002 finding)
  • Volatility mean-reversion: vol tends to revert; show it empirically via autocorrelation of vol^2
  • Drawdown analysis: duration and severity; difference between average and maximum drawdown

Pitfalls

  • Using overlapping windows without Newey-West corrections inflates t-statistics
  • Reporting only maximum drawdown; also report recovery time
Extension: Compute conditional Value-at-Risk (CVaR/ES) using historical simulation; compare to Gaussian VaR for 2008 and 2020 crash periods
03

Portfolio Construction and Risk Decomposition

Intermediate cvxpy · NumPy · statsmodels ~25 hours

Research Question: Does Markowitz mean-variance optimization produce better out-of-sample portfolios than the 1/N equal-weight benchmark, and what drives the performance difference?

Methodology

  • Select 30 stocks from different sectors; 15 years of data
  • Implement Markowitz optimizer with cvxpy: min-variance, tangency, maximum Diversification ratio
  • Apply shrinkage estimators for covariance: Ledoit-Wolf (scikit-learn); compare to sample covariance
  • Rolling walk-forward evaluation: 36-month estimation window, 1-month rebalance
  • Risk decomposition: marginal risk contribution, factor risk (market β, sector exposure)
  • Compare: MVO, equal-weight, inverse-vol weighted, maximum Sharpe

Key Lesson (Don't Skip This)

  • DeMiguel, Garlappi & Uppal (2009) show 1/N beats MVO on many datasets — demonstrate why (estimation error)
  • Show how extreme Markowitz weights arise from small changes in expected return estimates
  • Ledoit-Wolf shrinkage reduces extreme weights; explain the bias-variance tradeoff

Evaluation Metrics

  • OOS Sharpe, Sortino, Calmar, max drawdown, turnover, information ratio vs SPY
  • Bootstrap confidence intervals on the Sharpe ratio difference
Reference: DeMiguel, Garlappi & Uppal, "Optimal Versus Naive Diversification," RFS 2009 (SSRN freely available)

Backtesting Engine Built From Scratch

Intermediate Python OOP · pandas · pytest ~40 hours

Research Question: How do transaction costs, slippage, and position sizing assumptions alter strategy performance, and how can a backtesting framework prevent the most common biases?

Architecture

  • Event-driven design: DataHandler → SignalEngine → RiskManager → PortfolioManager → ExecutionHandler → Performance
  • Cost model: fixed commission per trade, percentage bid-ask spread (configurable), market-impact model (linear price impact)
  • Position sizing: equal-weight, volatility-scaled, Kelly criterion (fractional)
  • Accounting: cash tracking, long/short positions, daily P&L, unrealized vs realized, drawdown tracking
  • Bias prevention: price arrays only accessible up to current timestamp; no peeking at future prices

Tests to Write

  • Buy-and-hold test: verify P&L = (end price / start price - 1) minus costs
  • Look-ahead bias test: shift all signals by 1 day and verify performance degrades appropriately
  • Transaction cost test: zero-cost run vs 10bp cost run; measure performance delta
  • Survivorship bias test: run on S&P 500 current constituents only vs historical constituents

Momentum Strategy with Rigorous OOS Testing

Intermediate backtester (Project 4) · pandas ~30 hours

Research Question: Does the 12-1 cross-sectional momentum anomaly (Jegadeesh & Titman 1993) persist in recent data after transaction costs, and does it survive out-of-sample validation?

Implementation

  • Universe: S&P 500 historical constituents (handle survivorship bias — use point-in-time data from Wikipedia or Tiingo)
  • Signal: 12-month trailing return skipping the last month (12-1)
  • Portfolio: top and bottom quintile; long-short; monthly rebalance
  • Transaction costs: 10 bps one-way; measure annual turnover
  • OOS split: train 2000–2015, test 2016–present (strict date cutoff)
  • Variation study: test 6-1, 3-1, 12-3 formations; report ALL results (multiple testing!)

Statistical Rigor

  • Compute Newey-West t-statistic for mean monthly return (autocorrelation-corrected)
  • Bootstrap confidence intervals on Sharpe ratio (1000 block bootstrap samples)
  • Report: IS Sharpe, OOS Sharpe, t-stat, p-value, max drawdown, Calmar, annual turnover
  • Subsample stability: show performance by decade — is it stable?
  • Apply Bonferroni correction if testing multiple formation periods

Expected Honest Findings

Momentum has been weaker post-2010; crashes severely in reversals (2009, 2020). Be honest in your write-up about these limitations.

Reference: Jegadeesh & Titman (1993). Also read Israel & Moskowitz (2013) "The Role of Shorting, Firm Size, and Time on Market Anomalies" for a realistic cost-adjusted analysis.

Mean Reversion Strategy

Intermediate statsmodels · backtester ~25 hours

Research Question: Do short-term return reversals (Lehmann 1990; Lo & MacKinlay 1990) produce tradable alpha after realistic transaction costs?

Methodology

  • Weekly cross-sectional reversal: short last-week's winners, long losers
  • Test on US large-cap universe (Russell 1000 proxied by SPDR sector ETFs or individual stocks)
  • Vary holding periods: 1-week, 2-week reversal
  • Apply realistic bid-ask spreads (proportional to daily volume using Corwin-Schultz estimator or constant 5bps for large-caps)
  • Decompose: is alpha driven by bid-ask bounce, lead-lag, or true mispricing?

Key Insight

  • Short-term reversal is highly sensitive to transaction costs — this is the lesson
  • The gross signal is real; the net-of-cost signal is much smaller and regime-dependent
  • Discuss market impact: the more capital deployed, the worse execution quality

Pitfalls to Avoid

  • Using closing prices for both signal and execution — use next open or TWAP estimate
  • Ignoring turnover — this strategy turns over portfolio every 1–2 weeks

Pairs Trading with Cointegration Testing

Intermediate–Advanced statsmodels · arch · backtester ~35 hours

Research Question: Can cointegrated stock pairs identified in-sample generate statistically significant risk-adjusted returns OOS, and what is the role of hedge ratio estimation error?

Methodology

  • Universe: sector-matched pairs (e.g., XOM/CVX, KO/PEP, GS/MS)
  • Cointegration tests: Engle-Granger 2-step, Johansen trace test — implement both
  • Estimate hedge ratio via OLS; compare to Kalman filter dynamic hedge ratio
  • Spread: z_t = log(P1) - β·log(P2); standardize to z-score with rolling mean/std
  • Entry/exit: ±2σ entry, 0 exit; with stop at ±3σ
  • IS: 2010–2018 | OOS: 2019–present
  • Correct for multiple comparisons: if testing 100 pairs, apply FDR correction

Critical Analysis

  • How stable is cointegration? Test rolling cointegration over 2-year windows
  • What happens when the cointegrating relationship breaks? (thesis risk)
  • Transaction cost analysis: pairs trading requires frequent rebalancing
  • Report: number of trades, average holding period, OOS Sharpe, max drawdown per pair

Extensions

  • Kalman filter for dynamic hedge ratio estimation
  • Extend to 3-asset cointegrating systems (Johansen vectors)
  • Ornstein-Uhlenbeck model for the spread: calibrate θ, μ, σ and compute optimal entry threshold analytically

Fama–French Factor Analysis and Fama-MacBeth Regression

Intermediate–Advanced pandas · statsmodels · scipy ~30 hours

Research Question: Do size, value, profitability, and investment factor exposures explain cross-sectional variation in expected stock returns, and what is the marginal contribution of each factor?

Implementation

  • Download FF3 and FF5 factor returns from Ken French Data Library
  • Time-series regression: Rᵢ − Rf = α + β₁MKT + β₂SMB + β₃HML + εᵢ for each of 25 stock portfolios (FF25)
  • Fama-MacBeth 2-stage regression: (1) cross-sectional β estimation; (2) monthly cross-sectional return regression on β estimates; (3) time-series mean and t-stat of λ coefficients
  • Newey-West standard errors on λ (lags = 3)
  • Spanning test: does adding a new factor improve GRS test statistic?

Analysis

  • GRS (1989) test: joint test that all intercepts (alphas) are zero — implement and interpret
  • Compare FF3 vs FF5: does profitability and investment improve the model?
  • Check: is SMB premium stable across subperiods?
  • Discuss: value (HML) has been weak post-2007 — discuss structural vs sample variation explanation

Why This Is Interview-Essential

Fama-MacBeth regression is the standard procedure for cross-sectional asset pricing tests. Any QR role interviewer may ask: "How does Fama-MacBeth correct for cross-sectional correlation in the errors?" You should have a precise answer.

Black-Scholes Pricing, Greeks, and Implied Volatility Surface

Intermediate–Advanced scipy · numpy · matplotlib ~30 hours

Research Question: How does the market's implied volatility surface differ from the constant-volatility assumption of Black-Scholes, and what does this tell us about the model's limitations?

Implementation

  • Implement Black-Scholes from scratch: C = S·N(d₁) − K·e^{−rT}·N(d₂)
  • Compute all Greeks analytically: Δ, Γ, Θ, ν (Vega), ρ
  • Numerical Greeks: finite difference; verify they match analytical values
  • Implied volatility solver: Newton-Raphson using Vega; handle edge cases (deep ITM/OTM)
  • Download SPY options chain via yfinance or Polygon; construct IV surface
  • Visualize volatility smile and term structure

Key Analysis

  • Volatility smile: OTM puts have higher IV than ATM — implies market prices large negative jumps
  • Term structure: short-dated IV vs long-dated IV; behavior around macro events
  • Put-call parity check: verify it holds numerically in your data
  • Discuss: what does a non-flat IV surface imply about the adequacy of GBM as a model for stock prices?

Extensions

  • Implement Heston model variance swap formula
  • Dupire local vol surface extraction from market prices
  • Delta-hedging simulation: P&L under real vs implied vol

Monte Carlo Option Pricing and Variance Reduction

Intermediate–Advanced numpy · scipy ~25 hours

Research Question: How do different Monte Carlo variance reduction techniques affect the speed-accuracy tradeoff for option pricing, and when does MC have advantages over analytical solutions?

Implementation

  • GBM path simulation: S(T) = S₀·exp((r − σ²/2)T + σ√T·Z), Z∼N(0,1)
  • European call/put pricing; verify against Black-Scholes closed-form
  • Variance reduction: (1) Antithetic variates; (2) Control variates; (3) Importance sampling
  • Convergence analysis: RMSE vs N_simulations; plot convergence curves for each method
  • Asian option (arithmetic average): MC is needed — no closed form
  • Barrier option pricing: up-and-out call
  • American option: Longstaff-Schwartz least-squares MC for early exercise

Key Lessons

  • MC error scales as 1/√N — to halve error, need 4× more simulations
  • Antithetic variates roughly halves variance for free; always use it
  • Control variate using geometric Asian as control for arithmetic Asian is textbook and powerful
  • Longstaff-Schwartz shows how to handle path-dependent early exercise — foundational for American options

Performance Testing

  • Time your implementations; explore NumPy vectorization vs Python loops
  • Profile with cProfile to find bottlenecks

Volatility Forecasting with GARCH Models

Intermediate–Advanced arch · statsmodels · scipy ~30 hours

Research Question: Which volatility model — realized volatility, EWMA, GARCH(1,1), GJR-GARCH, or EGARCH — produces the most accurate 1-day and 22-day ahead volatility forecasts?

Models to Implement

  • RV: rolling 21-day realized variance
  • EWMA: σ²_t = λσ²_{t-1} + (1-λ)r²_{t-1}; tune λ via MLE
  • GARCH(1,1): σ²_t = ω + αε²_{t-1} + βσ²_{t-1}; MLE estimation
  • GJR-GARCH: adds asymmetric leverage effect (γ coefficient on negative innovations)
  • EGARCH: Nelson (1991) — log specification ensures positive variance without constraints
  • Use arch library; then implement GARCH(1,1) MLE from scratch to understand it

Evaluation Framework

  • True volatility proxy: realized variance from 5-minute intraday returns (if available) or absolute daily returns squared
  • Forecast evaluation: MSE, QLIKE loss (preferred for volatility: asymmetric), Mincer-Zarnowitz regression
  • Diebold-Mariano test for forecast comparison
  • Rolling OOS evaluation: expand window, forecast 1 step ahead

Key Financial Result

GJR-GARCH typically outperforms GARCH(1,1) for equities due to leverage effect (negative returns increase future vol more than positive returns of same magnitude — Black 1976).

Market Microstructure and Limit Order Book Analysis

Advanced Python · pandas · LOB data ~35 hours

Research Question: What empirical regularities exist in limit order book dynamics, and how do bid-ask spreads, order imbalance, and trade clustering relate to short-term price movements?

Methodology

  • Data: Nasdaq BBO data via LOBSTER (lobsterdata.com) or IEX TOPS feed (free)
  • Bid-ask spread estimation if only daily data: Corwin-Schultz (2012) high-low estimator
  • Roll (1984) implied spread from return autocorrelation
  • Order flow imbalance: OFI = (bid volume change − ask volume change)
  • Regression: price change ~ OFI + lagged OFI (Cont, Kukanov & Stoikov 2014)
  • Intraday patterns: spreads, volume, volatility by time of day

Models

  • Amihud (2002) illiquidity ratio: |r_t|/Volume_t — cross-sectional and time-series analysis
  • Kyle (1985) λ estimation: regress price change on signed volume
  • Hasbrouck (1991) VAR model for quote revisions and trades

What Makes This Credible

Most quant candidates skip microstructure. Demonstrating knowledge of Kyle's lambda, the Amihud ratio, and order flow imbalance immediately signals that you understand execution costs — a key concern for any live strategy.

Statistical Arbitrage with Strict Out-of-Sample Discipline

Advanced sklearn · statsmodels · backtester ~45 hours

Research Question: Can a multi-factor statistical arbitrage strategy using PCA-extracted latent factors generate statistically significant OOS alpha with realistic execution assumptions?

Methodology

  • Universe: S&P 500 constituents; 15 years daily data; handle survivorship bias
  • PCA on return matrix: extract top K factors; residual = idiosyncratic return
  • Mean-reverting signal: standardized residual (z-score) over rolling 60-day window
  • Portfolio: long top decile by positive z-score, short bottom decile
  • Risk constraints: sector-neutral, β-neutral (market exposure < 0.1), position limits
  • Strict OOS: IS 2005–2018, OOS 2019–present; never touch OOS until final evaluation

Rigor Requirements

  • Walk-forward validation within IS period first
  • Report probability of backtest overfitting (PBO) using combinatorially symmetric cross-validation (Bailey et al. 2017)
  • Transaction costs: 5bps per side; measure monthly turnover
  • Deflated Sharpe Ratio (DSR) — adjust Sharpe for skewness, kurtosis, and multiple testing
  • Honest OOS assessment: IS Sharpe 1.2, OOS Sharpe 0.6 — still a realistic finding

Common Failure Mode

PCA factors are not stable over time. Regime changes cause factor rotations. Use rolling PCA or retrain periodically within walk-forward loop.

Machine Learning for Return Prediction with Leakage Controls

Advanced xgboost · lightgbm · sklearn · mlflow ~50 hours

Research Question: Can gradient-boosted trees trained on lagged financial features generate statistically significant Information Coefficient (IC) for next-month stock returns, and does the IC survive purged walk-forward validation?

Features (All Strictly Lagged)

  • Momentum: 1m, 3m, 6m, 12m return
  • Reversal: 1w, 2w return
  • Volatility: 21-day realized vol; GARCH vol estimate
  • Value: P/E, P/B, dividend yield (from EDGAR via simfin)
  • Quality: ROE, ROA, gross profitability, debt/equity
  • Technical: RSI-14, MACD, Bollinger band position
  • Each feature must be computable at time T using only data available at T

Validation Discipline

  • Purged K-Fold CV: drop observations overlapping the test fold ± embargo period (Lopez de Prado Ch.7)
  • Feature engineering leakage: rolling means computed only on past data; verify with shifted data test
  • Target: 1-month forward return (realized next month, not available at prediction time)
  • IC: Spearman rank correlation between predicted and realized returns; ICIR = mean(IC)/std(IC)
  • Compare: ICIR in IS vs ICIR in OOS; if OOS ICIR < 0.3, signal is likely too weak

MLflow Experiment Tracking

  • Log every hyperparameter, training window, OOS IC, and Sharpe to mlflow
  • This prevents p-hacking and gives you an honest audit trail

Complete Research Pipeline: Systematic Equity Strategy

Advanced — Capstone Full stack: data → signal → portfolio → execution → report ~80+ hours

Research Question: Can a systematic equity strategy combining momentum, quality, and low-volatility factors achieve a risk-adjusted excess return (Deflated Sharpe > 1.0) after all costs in out-of-sample data?

Pipeline Architecture

  1. Universe construction: S&P 500 historical constituents; liquidity filters; point-in-time
  2. Signal generation: each factor z-scored cross-sectionally; composite signal = weighted average
  3. Portfolio optimizer: mean-variance with signal as alpha input; risk model = Ledoit-Wolf covariance; constraints: long-only, max weight 3%, sector ±5% from benchmark
  4. Transaction cost model: linear market impact + proportional spread; turnover budget constraint
  5. Risk limits: stop-loss at −8% monthly, max β = 0.15 from neutral, max sector weight 20%
  6. Execution model: TWAP over first 2 hours of day; partial fills
  7. Walk-forward engine: 36-month IS window, 3-month OOS, refit every 6 months

Performance Attribution

  • Brinson-Hood-Beebower attribution: allocation effect, selection effect, interaction
  • Factor attribution: how much of alpha is explained by FF5 factors?
  • Sharpe, Sortino, Calmar, max drawdown, avg drawdown duration, turnover, information ratio
  • Deflated Sharpe Ratio (Bailey & Lopez de Prado 2012) — adjusts for multiple testing

Research Report Requirements

  • 1-page executive summary with hypothesis, method, key results (not cherry-picked)
  • Honest OOS assessment: where did it underperform? Why?
  • Regime analysis: performance during risk-off vs risk-on periods
  • Limitations section: data quality, survivorship bias mitigation, capacity estimate
  • All code reproducible with one command: make backtest

Why This Is Capstone-Quality

This project integrates everything: econometrics, optimization, execution, risk management, and scientific reporting. A well-executed version of this — with honest OOS results — is more impressive to quant interviewers than any result that looks too good.

Target deliverable: Public GitHub repo · Full research report PDF · Reproducible Docker environment · Presentation deck (5 slides max: hypothesis, methodology, results, risks, next steps)
